Executive Verdict
Ship with fixes
The storefront is emotionally articulate and technically lean, but ships with three weight-bearing conversion bugs: the /about page CTA silently dies (no BuyButton mounted), the price is never shown before checkout, and ContactForm.jsx still uses mailto: despite the docs claiming FormSubmit AJAX. The architecture is right-sized for one product; the issues are execution gaps between what shipped and what the docs say shipped. Fix the conversion path, surface the price and product name, kill the orphan contact form. Then go find five real strangers.

Critical Path — If You Only Have 2 Hours

  1. Conversion: Fix /about CTA — mount <BuyButton> on About, or link the button to /#shop. Currently dies silently for anyone arriving from social shares or Instagram bio.
  2. Trust: Surface product name, card count, and NZD price on the homepage before the CTA. Buyer should never see the price for the first time inside the cart drawer.
  3. Communications: Migrate src/components/ContactForm.jsx from mailto: to FormSubmit AJAX (Footer pattern already works). Stops leaking Jesse's email and fixes the broken contact path on devices without configured mail.
  4. Narrative: Drop the Instagram feed from Home (keep on About). It breaks the emotional arc between the testimonial and the CTA. Let "Just begin" be the last sound.
  5. Operations: Move Instagram URLs, testimonials, and product ID from JS source into Firestore (the portal already has the plumbing). Jesse stops pinging Joel for content swaps.
  6. Security: Add a Content-Security-Policy + Referrer-Policy + Permissions-Policy via firebase.json headers config. Currently only HSTS ships.

The hero's JS-driven right calculation between 1024px and 2190px is a clever projector, the clamp() typography flexes without me having to think, the mobile card expand-and-flip uses translate/scale instead of position: fixed because someone already learned that transform ancestors eat fixed positioning. Good projector work there. The reduced-motion media query catches everything. The pointer: coarse glow fallback is thoughtful. But pour it into the 768 to 1023 band and something puddles. The sticky-section stack activates at min-width: 768px. The hero's min-h-[85svh] activates at lg which is 1024px. Between those two breakpoints, the hero is a sticky-section with no enforced minimum height, sitting under the next sticky-section in z-stacking order. If the hero's natural content height is shorter than the ScriptureInterlude's md:min-h-screen (which it almost certainly is on iPad portrait at 768x1024), the sticky illusion breaks. The scripture section doesn't slide over a pinned hero, it slides into a gap. Structure without containment. The Hero also drops its desktop image at lg:block (1024px). So in that same 768-1023 band, the mobile cover image renders at h-[470px] object-cover underneath text that's center-aligned because lg:text-left hasn't kicked in. Two viewport widths from the same design language and they don't talk to each other. The breakpoint at md: (768px) governs typography and spacing, the breakpoint at lg: (1024px) governs the hero's entire layout philosophy. Tablets fall between the two and inherit a half-mobile, half-desktop shape. The InteractiveCards CSS overrides at 1200/768/480px use [style*='--card-w'] attribute selectors with !important to force --card-w and the wrapper height. That works, but only because the wrapper has --card-w in its inline style. Any future card grid that doesn't use that exact CSS variable name will not adapt. The projector is hardcoded to one shape. Fix shape, in priority order. One: align the breakpoints. Either move sticky-section activation up to lg (1024px), or add md:min-h-[85svh] to the hero so the 768-1023 band has structural height. Two: add a mid-breakpoint hero layout (md: text-left with no big image), or just hide the mobile image at md: and show the desktop one. Three: replace the [style*='--card-w'] selector with a class on the wrapper so the responsive contract is named, not inferred. Small fixes. Without them, iPad-portrait visitors get the leaky version of this site.
