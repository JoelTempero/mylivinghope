My Living Hope — Architecture Overview

Two independent subsystems sharing Firebase as the backbone

SUBSYSTEM 1

Headless Storefront

Replace Shopify Liquid with custom Next.js site

FRONTEND
Next.js + React + Tailwind
Full creative control, SSR for SEO
COMMERCE API
Shopify Storefront API (GraphQL)
Products, collections, cart, checkout
HOSTING
Vercel or Firebase Hosting
mylivinghope.org.nz
SUBSYSTEM 2

Shared AI Context Layer

Give both machines' Claude Code shared business intelligence

SHARED CONTEXT
MLH-CONTEXT.md in Firebase Storage
Session logs, decisions, priorities
ON-DEMAND DATA
MCP Server + CLI scripts
Query Firestore collections as needed
SYNC TRIGGER
Portal "Sync Context" button
Cloud Function → Storage upload
SHARED BACKBONE
Firebase
Auth · Firestore · Storage · Hosting
|
Shopify
Products · Inventory · Checkout · Orders
|
Portal (React + Vite)
Existing admin CRUD · portal.mylivinghope.org.nz

Key principle: Each subsystem is independently buildable and deployable. The storefront doesn't depend on the AI context layer, and vice versa. Firebase is the connective tissue.
